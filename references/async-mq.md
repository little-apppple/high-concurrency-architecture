# 异步化与消息队列（异）

## 1. 核心思想

把同步调用链中非核心、耗时的逻辑异步化（发短信、写日志、扣积分、更新报表），缩短主链路响应时间；MQ 同时充当缓冲池，将瞬时流量洪峰暂存，由消费者按自身处理能力匀速消费，即"削峰填谷"。

## 2. MQ 选型

| 产品 | 特点 | 适用场景 |
|---|---|---|
| Kafka | 高吞吐、持久化、分区有序 | 日志采集、大数据管道、事件流 |
| RocketMQ | 高吞吐 + 低延迟，事务消息、延时消息 | 电商交易、订单异步化 |
| RabbitMQ | 路由灵活、可靠性高 | 业务解耦、任务队列 |
| 云托管（SQS/PubSub） | 全托管、弹性 | 云原生、Serverless |

## 3. 削峰填谷设计

- 写请求先入队立即返回受理成功，下游按 DB 承受能力平滑消费。
- 通过调节消费者并发数控制处理节奏，资源始终在可控范围。
- 量化示例：写接口 1w QPS 峰值，MQ 削峰后按 2k/s 平滑消费。
- 代价：牺牲实时强一致性，换取高可用与吞吐，用最终一致性。

## 4. 消息可靠性

三个环节都不能丢：
1. 生产端：发送确认（ack）+ 失败重试 + 本地消息表/事务消息。
2. Broker：持久化 + 多副本。
3. 消费端：手动 ack，处理成功后才确认；失败进重试队列/死信队列。

## 5. 幂等设计

重试必然带来重复投递，消费端必须幂等：
- 唯一业务 ID + 去重表/Redis setnx。
- 数据库唯一约束兜底。
- 状态机：只允许合法状态流转（如"已支付→已发货"不可逆）。

## 6. 秒杀案例范式

1. 前端拦截：按钮防重、验证码、静态页 + CDN，99% 请求挡在入口。
2. 网关限流：令牌桶控制进入后端的请求量。
3. Redis 预扣库存：Lua 脚本原子扣减，拒绝超卖。
4. MQ 异步下单：扣减成功后发消息，订单服务匀速消费创建订单。
5. 兜底：DB 乐观锁防超卖，非核心逻辑（通知、积分）完全异步。

## 7. 其他异步手段

- 同步链路内能并行就并行（并发任务/异步编排聚合多下游，再统一组装结果）。
- I/O 密集场景用 Netty（非阻塞 I/O）或协程，以极小线程开销支撑海量连接。
