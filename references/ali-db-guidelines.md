# 后端通用数据库规约（提炼自《阿里巴巴 Java 开发手册》黄山版）

来源：alibaba/p3c 官方仓库《Java 开发手册（黄山版）》第五章 MySQL 数据库 + 第六章服务器 + 第七章设计规约中与语言无关的部分。已剔除 Java/ORM 框架专属条目。

## 1. 建表规约

【强制】
- 布尔语义字段用 `is_xxx` 命名，类型 unsigned tinyint（1 是 / 0 否）；非负数字段必须 unsigned。
- 表名、字段名只用小写字母和数字，下划线分隔，禁数字开头；禁用保留字（desc、range、match、delayed 等）。MySQL 在 Linux 下默认区分大小写，命名禁止大写字母。
- 表名用单数名词，推荐 `业务名称_表的作用` 格式（如 trade_config）。
- 小数用 decimal，禁 float/double（精度损失导致比较错误）；超出 decimal 范围则整数、小数分开存储。
- 等长字符串用 char；varchar 长度不超 5000，超过用 text 独立成表、主键对应，避免影响其他字段索引效率。
- 表必备三字段：id（bigint unsigned，单表自增步长 1）、create_time、update_time（datetime；需时区信息用 timestamp）。
- 禁止物理删除，用逻辑删除（如 is_deleted）。
- 主键索引 pk_字段名，唯一索引 uk_字段名，普通索引 idx_字段名。

【推荐】
- 单表行数超 500 万行或容量超 2GB 才分库分表；预计三年达不到该量级就不要预分。
- 字段允许适当冗余提升查询性能，冗余字段须满足：非频繁修改、非唯一索引、非超长 varchar/text。
- 字段含义或状态变更时及时更新注释。

【参考】用小类型省空间提速：tinyint unsigned（0~255）→ smallint unsigned（0~65535）→ int unsigned → bigint unsigned，按实际区间选。

## 2. 索引规约

【强制】
- 业务上唯一的字段（含组合字段）必须建唯一索引：insert 损耗可忽略，应用层校验挡不住墨菲定律。
- 超过三个表禁止 join；join 字段数据类型绝对一致，被关联字段必须有索引；双表 join 也要关注索引与 SQL 性能。
- varchar 索引必须指定索引长度，用 `count(distinct left(列, 长度)) / count(*)` 确定区分度（长度 20 常可达 90%+）。
- 页面搜索严禁左模糊/全模糊（违反 B-Tree 最左前缀），全文检索走搜索引擎。

【推荐】
- order by 字段放入组合索引末位避免 filesort；`where a=? and b=? order by c` → 索引 a_b_c。
- 覆盖索引避免回表（explain Extra 出现 using index）。
- 深分页用延迟关联：先定位 id 段再回表关联。
- SQL 性能目标：至少 range，要求 ref，最好 const；type=index（索引全扫描）比 range 还差。
- 组合索引区分度最高的在左；等号与范围混合时等号列前置（`where c>? and d=?` → idx_d_c）。
- 防止字段类型隐式转换导致索引失效（如 varchar 列用数字查）。

## 3. SQL 语句规约

【强制】
- 统计行数用 count(*)（SQL92 标准，与 NULL 无关）；count(列名) 不统计 NULL 行。
- count(distinct col1, col2) 中任一列全 NULL 则返回 0；列全 NULL 时 count(col)=0 但 sum(col)=NULL，用 IFNULL(SUM(col), 0) 防空指针/空值异常。
- NULL 判断用 ISNULL()：NULL 与任何值比较结果都是 NULL，不是 true/false。
- 分页逻辑中 count 为 0 直接返回，不执行后续分页查询。
- 不得使用外键与级联，一切外键概念在应用层解决。官方理由：外键与级联更新只适合单机低并发；级联更新是强阻塞，存在数据库更新风暴风险；外键影响插入速度。
- 禁止使用存储过程：难以调试和扩展，无移植性。
- 数据订正（尤其删改）必须先 select 确认，再执行更新。
- 多表查询/变更时列名必须加表别名限定，避免字段歧义（Column ambiguous 异常）。

【推荐】
- 表别名加 as，按 t1/t2/t3 顺序命名。
- in 操作尽量避开，避免不了时集合元素控制在 1000 个以内。

【参考】
- 字符集统一 utf8mb4（支持 emoji），注意 LENGTH() 按字节、CHARACTER_LENGTH() 按字符。
- TRUNCATE 比 DELETE 快且省日志，但无事务、不触发 trigger，开发代码中不建议使用。

## 4. 通用数据访问规约（原 ORM 节去语言化）

【强制】
- 查询一律不用 `SELECT *`，明确列出字段：降低解析成本、避免无用大字段网络消耗、防止字段变更引发映射不一致。
- SQL 参数绑定禁止字符串拼接（防 SQL 注入），一律用占位符参数化查询。
- 不用大而全的更新接口：更新时只 set 变更字段，不无脑全量更新（易错、低效、膨胀 binlog）。
- 更新记录必须同时更新 update_time 为当前时间。
- 结果集映射类型必须显式定义，禁止用无 schema 的动态结构（原 Map/HashMap 条目的通用化：类型失控，依赖 DB 驱动版本行为）。

【参考】
- 事务最小化：事务影响 QPS，开启事务前考虑回滚方案（缓存回滚、搜索引擎回滚、消息补偿、统计修正）。

## 5. 服务器规约（高并发相关）

【强制】
- 远程调用必须有超时设置；无数次故障源于未设 Timeout。

【推荐】
- 高并发下调小 TCP time_wait 超时：Linux `net.ipv4.tcp_fin_timeout=30`（默认 240s 会耗尽连接）。
- 调大最大文件句柄数（fd）：默认 1024，高并发下报 "too many open files"。
- 线程池隔离：按服务平均耗时独立配置线程池，慢服务与主线程池隔离，避免拖垮全部线程。

## 6. 设计规约（与稳定性相关条目）

【强制】
- 存储方案和底层数据结构设计必须评审通过并沉淀文档，含：存储介质选型、表结构、存取性能与空间、表/字段关系、索引。
- 系统依赖准确识别弱依赖，针对性设计降级与应急预案，保证核心链路可用。下游平均 RT 或错误率超阈值时自动降级/熔断，屏蔽弱依赖负面影响。
