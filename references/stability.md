# 稳定性保障（限流 / 熔断 / 降级 / 扩容）

## 1. 限流（水）

控制进入系统的请求总量，过载时宁可拒绝部分请求，也要保整体存活。

| 算法 | 特点 | 适用 |
|---|---|---|
| 令牌桶 | 允许一定突发流量 | 保护 API 接口 |
| 漏桶 | 强制恒定流出速率 | 保护数据库等脆弱下游 |
| 滑动窗口/计数器 | 简单直观 | 网关粗粒度限流 |

分层实施：网关层（Nginx/Sentinel）→ 应用层 → 数据库层（连接池上限）。
组件：Sentinel、Hystrix、网关自带限流模块。

## 2. 熔断

- 下游服务错误率或响应时间超阈值 → 熔断器打开，直接快速失败，防止级联雪崩。
- 三态转换：关闭 → 打开 → 半开（试探请求，恢复后完全恢复）。
- 实现：Sentinel、Resilience4j、Hystrix（经典）。

## 3. 降级

- 系统压力过大时关闭非核心功能，保核心业务可用（如大促时关闭推荐、评论）。
- 降级策略必须提前设计：返回默认值、缓存旧数据、简化流程。
- 区分核心/非核心链路是降级设计的前提。

## 4. 隔离

- 资源隔离防止单点拖垮整体：线程池隔离、信号量并发控制、容器 CPU/内存配额（Docker/K8s）。
- 热点数据单独部署，与常规流量隔离。
- 代码层信号量控制同时访问特定资源的线程数，防热点击穿缓存瞬间压垮后端。

## 5. 水平扩容与容量水位

- 前提：应用无状态化。Session、计数器等状态外置到 Redis/JWT。
- 扩容路径：先垂直扩到合理规格（性价比拐点前），再水平扩容；Web 层易水平扩展，数据层往往先垂直。
- 日常水位控制在 50%~60%，给突发流量留余量。
- 配合弹性伸缩（K8s HPA / 云自动扩缩容）+ 限流兜底。

## 6. 可观测性

- 全链路监控（SkyWalking、Zipkin、OpenTelemetry）快速定位瓶颈与故障点。
- 关键指标：响应时间、错误率、吞吐量、资源利用率、缓存命中率、队列积压。
- 结构化日志 + 集中采集 + 分布式追踪；从被动响应转向主动预防。

## 7. 负载均衡

- 软件层：Nginx（L7 灵活）、HAProxy（L4/L7）；云托管：ALB/NLB。
- 算法：轮询、加权轮询、最少连接、IP Hash（会话保持）。
- 职责：流量分发、SSL 终止、基础过滤、健康检查自动摘除故障节点。
