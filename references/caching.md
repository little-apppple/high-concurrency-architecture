# 缓存范式（缓）

## 1. 多级缓存体系

请求路径由外到内层层过滤，每一层拦截一部分流量：

```
浏览器本地缓存 → CDN 边缘缓存 → 网关/Nginx 缓存 → 应用本地缓存(Caffeine/Guava) → 分布式缓存(Redis) → 数据库
```

- 读多写少的数据优先缓存；合理使用可拦截 90% 以上请求。
- 静态资源由 CDN / 浏览器消化；动态请求优先命中 Redis。
- 本地缓存适合极热、可容忍短暂不一致的数据（进程内内存缓存，如 Guava/Caffeine/Nginx 缓存，视技术栈选择）；分布式缓存适合共享热点数据。
- Redis 典型用途：Session、热点数据、分布式锁（秒杀库存扣减）、计数器（点赞/浏览量）、排行榜（Sorted Set）。

## 2. 常用缓存模式

| 模式 | 做法 | 特点 |
|---|---|---|
| Cache Aside（最常用） | 读：先缓存，miss 读库回填；写：先更新库，再删缓存 | 灵活，最终一致 |
| Read Through | 应用只和缓存交互，缓存自行取数 | 对应用透明 |
| Write Through | 写时同步更新缓存和库 | 一致性好，延迟高 |
| Write Behind | 写只更新缓存，异步刷库 | 性能好，有丢失风险 |

## 3. 三大经典缓存问题

| 问题 | 现象 | 解法 |
|---|---|---|
| 缓存穿透 | 查询不存在的数据，每次都打到 DB | 缓存空值；布隆过滤器拦截无效 Key |
| 缓存击穿 | 热点 Key 过期瞬间，海量请求压到 DB | 互斥锁只放一个请求重建；"永不过期"逻辑 + 后台异步刷新 |
| 缓存雪崩 | 大量 Key 同时失效，DB 被冲垮 | 过期时间加随机值；多级缓存兜底 |

## 4. 一致性策略

- 主流方案：Cache Aside + 最终一致性。
- 延时双删：写库后删缓存，延迟几百毫秒再删一次，覆盖并发读回填的旧值。
- 订阅 Binlog（Canal）异步更新/删除缓存，解耦业务代码。
- 强一致场景：读走主库，或用版本号/时间戳校验。

## 5. 热点与预热

- 大促/上线前对核心热点数据做缓存预热，提前加载到内存。
- 热点 Key 单独隔离部署，避免拖垮整个缓存集群。

## 6. 量化示例

某读接口 10w QPS，多级缓存命中率 95% 后仅 5k QPS 打到 DB。先算清楚每层压力，再决定缓存层级与容量。
