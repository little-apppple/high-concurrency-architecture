# 反模式与 FAQ（避坑指南）

高频错误做法、常见疑问与组合场景细节。设计原则见 SKILL.md 关键权衡原则，本册讲"别人踩过的坑"。

## 1. 反模式清单

| 反模式 | 为什么错 | 正确做法 |
|---|---|---|
| 上来就微服务拆分 | 团队小、边界不清时拆分成本 > 收益，运维复杂度指数上升 | 单体模块化 → 量级到了再拆 |
| 预分库分表 | 预计三年到不了 500 万行/2GB，提前分是自找分布式事务 | 单表 + 索引优化，留好分片键即可 |
| 缓存一切 | 写多读少数据缓存命中率低，反增一致性维护成本 | 只缓存读多写少 + 可容忍不一致的数据 |
| 用 MQ 解决一切异步 | 强一致链路（如扣款）异步化会造成资损 | 只异步化非核心、可补偿的链路 |
| 过早引入新技术组件 | 每个中间件都是运维负债 | 同类单主力，先答"扩容/监控/降级"三问 |
| 限流阈值拍脑袋 | 过严误杀、过严等于没限 | 压测容量 × 0.8，且必须可动态调整 |
| 重试无上限无退避 | 故障时重试风暴压垮下游 | 指数退避 + 最大次数 + 熔断兜底 |
| 超时层层放大 | 外层超时 > 内层，调用方等死 | 外层 ≥ 内层且整体有预算（deadline 传递） |
| 分布式锁不分场景 | 主从切换丢锁导致超卖 | 极端一致性改用 CP 组件（ZooKeeper/etcd） |
| 大事务包裹远程调用 | 事务内 RPC 拉长持锁时间，拖垮连接池 | 事务最小化，RPC 移出事务，用最终一致补偿 |

## 2. 常见问题 FAQ

**Q1：缓存和数据库的一致性到底怎么选？**
按容忍度分级：能容忍秒级不一致 → Cache Aside 删缓存即可；要求更低 → 延时双删或 Binlog 订阅；要求强一致 → 读主库，放弃缓存一致性优化。不要一开始就上最重的方案。

**Q2：分库分表后跨分片查询怎么办？**
主查询路径靠分片键路由；多维查询走异构索引（ES/宽表）同步；统计类走离线数仓。禁止运行时全分片扫描聚合。

**Q3：MQ 消息积压了怎么紧急处理？**
先定位是消费逻辑慢还是下游限速；扩容消费者受分区数上限约束（消费者数 ≤ 分区数），不够就新建大分区 topic 快速转发消费；长期靠提前容量规划。

**Q4：限流、熔断、降级什么区别？什么时候用哪个？**
限流是入口侧主动拒绝超额流量（保护自己）；熔断是下游故障时快速失败（保护自己不被拖死）；降级是压力下关闭非核心功能（保核心）。过载防护三件套通常组合使用，见 stability.md。

**Q5：热点 Key 除了打散还有什么办法？**
本地缓存挡在最前（进程内缓存秒级更新）；读写分离扩从库；极端热点单独部署隔离；Key 值本身压缩减小网络开销。

**Q6：无状态化到底指什么？**
应用实例不存任何请求间状态：Session 外置 Redis/JWT、文件外置对象存储、定时任务用分布式锁选主。唯一判据：杀掉任意一台实例重建，业务无损。

**Q7：容量估算从哪开始？**
从入口 QPS 倒推：峰值 QPS → 每层过滤比（CDN/缓存命中率）→ 各层真实压力 → 按 50%~60% 水位选规格。没有量化就没有架构决策。

## 3. 复杂组合场景细节

### 组合一：缓存 + 分库分表
- 缓存 Key 必须携带分片键语义（如 `order:{user_id}:123`），避免缓存层二次路由混乱。
- 分表扩容（rehash 迁移）时缓存双写/灰度切换，防止新旧分片数据混读；迁移期用版本号隔离缓存。
- Binlog 订阅更新缓存要按分片并行消费，防单消费者成为吞吐瓶颈。

### 组合二：MQ + 分布式锁
- 消费端幂等去重若用 Redis 锁，锁的过期时间必须 > 消费耗时，否则去重失效重复消费。
- 锁失败的处理策略要明确：快速失败回滚消息（延迟重投），不要在消费者里自旋等锁。

### 组合三：限流 + 熔断 + 扩容联动
- 扩容生效有延迟（分钟级），限流是扩容到位前的过渡保护，两者必须同时配。
- 熔断大量打开时说明容量不足或下游故障，先看是否触发自动扩容，再考虑人工介入。
- 大促预案顺序：预热 → 提前扩容 → 收紧限流 → 按预案降级，逐级启用而非同时生效。

## 4. 需求模糊时的处理范式（给使用本 skill 的 Agent）

- 用户只说"做个高并发系统"而未给量级：必须先确认四个要素（峰值 QPS、读写比、数据量级、一致性要求），再给方案；拒绝直接输出泛泛架构图。
- 用户场景不明时，按最接近的典型场景（电商交易/内容分发/社交 feed/秒杀脉冲）给出假设并声明假设，方案随之收敛到对应范式组合。
- 给出的每个方案必须带量化依据（每层压力数字），避免"建议加缓存"这类无依据表述。
